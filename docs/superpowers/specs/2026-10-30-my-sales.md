# My auctions management

User approved read-only seller management: status counts/filter, title search and
sorting, highest price/bid count/end time, refresh/error/empty recovery, and rename
the mypage menu to 내 경매. No seller edits/cancellation/payment mutations.

Current FE reads a legacy catalog users endpoint. Add GET /api/v1/auctions/mine to
the active auction service; JWT-verified seller only, private/no-store. Application
service/port and PostgreSQL adapter with an additive owner/date/id index.

Query: q trimmed <=80 chars (literal substring, no wildcard syntax), status
all|waiting|active|ended|hidden|cancelled, sort recent|ending|price, page integer
1..10000, default all/recent/1. Page size20. Deterministic tie-break auctionId DESC.
Recent=createdAt DESC, ending=endAt ASC, price=greatest(currentBid,minimumBid) DESC.
No client owner ID. Reject unknown keys, arrays and malformed inputs with400.

Exclude soft-deleted auctions even for owner. Hidden/cancelled are owner-only
statuses; otherwise now>=endAt ended, now<startAt waiting, else active. Summary
counts all own nondeleted auctions; total is filtered count. List and counts share
one repeatable-read snapshot/server timestamp. Bid count counts nondeleted bid
records, not distinct people. Return only public display fields: UUID/title/image,
decimal-string min/current price, numeric safe counts, dates/status. No buyer,
bidder, payment, private owner or description fields. No per-card HTTP calls.

FE /mypage/sales uses URL-backed GET controls, summary, 20 cards/page, page links
preserving filters, first-page recovery for out-of-range pages, KST labels, refresh,
separate API error/empty/no-results. Full summary is not affected by current filter.
Hidden/cancelled cards have no misleading public-detail link. Ended is not sold.
Unknown/malformed upstream results become fixed Korean error, never false empty.
Reuse existing rejected-session recovery by giving its component a general auth
name (SessionSignInButton), preserving saved-auctions behavior. No new packages.

Offset paging fits portfolio volumes; stable ordering is not a snapshot across
separate requests if data changes. At most10000 pages are exposed; future scale
may replace this with cursor paging. Status/price updates require refresh.

No local Docker or production test DB. Real PostgreSQL only guarded disposable
loopback _test in full CI. Backend migration/ready before FE publish. Existing
canonical repos and main commit/push/deploy authorization apply; no worktrees.
Live validation is read-only using existing demo account, no seed/bid/payment.
