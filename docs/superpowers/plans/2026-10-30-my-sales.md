# My Auctions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans inline. Steps use checkbox syntax for tracking.

**Goal:** Give sellers a useful authenticated read-only auction management page.
**Architecture:** JWT controller → application service/port → PostgreSQL snapshot;
Next server action → server-rendered URL filters/list and client refresh/re-login.
**Tech Stack:** Existing Nest/Fastify/Prisma/PostgreSQL/Next; no new dependencies.
**Spec:** docs/superpowers/specs/2026-10-30-my-sales.md

## Global Constraints

- JWT owner only; soft deletes excluded, hidden/cancelled private; no financial writes.
- Query q<=80/status6/sort3/page1..10000, pageSize20; exact money strings and KST.
- Counts/list same snapshot, deterministic sort; no per-card API/N+1 requests.
- No local Docker/prod DB tests; additive index; backend ready before FE release.

## Review Focus

- Forged/header/query identity and static-route ambiguity cannot disclose another seller.
- Hidden/cancelled/deleted status and exact time boundaries match summary and filtering.
- Search treats %, _, quotes literally; sort ties/paging/large money remain precise.
- Expired cookies can recover to sign-in; errors are not rendered as empty success.
- Page links/reset/filter changes preserve intended state and mobile remains usable.
